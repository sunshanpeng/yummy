## 1. 交付与使用

[打开交互原型](../../prototypes/v1-build-console/index.html)。直接用浏览器打开，不依赖后端、CDN 或新安装的依赖；默认进入工作空间的应用首页。

原型是独立 HTML/CSS/JavaScript，用于审查布局和交互，正式产品仍采用 React 技术栈。所有数据、登录、上传、OAuth、构建、部署、运行、监控和权限均为示例，不连接真实后端，不保存输入凭证。检查范围见 [QA](../../prototypes/v1-build-console/QA.md)。

## 2. 信息架构与日常/管理分离

```text
登录 / 接受邀请（OAuth 确认在第一版之后）
├── 个人账户（每位用户，独立于工作空间）
│   ├── 个人概览
│   ├── Agent 接入（CLI 与本地 MCP）
│   └── 个人访问令牌
├── 工作空间
│   ├── 应用列表（日常首页）
│   │   └── 应用详情（独立应用管理页）
│   │       ├── 概览 / 发布 / 构建 / 日志 / 监控 / 变量
│   │       └── 配置
│   │           ├── 运行设置
│   │           ├── 构建设置（含本应用构建密钥）
│   │           └── 成员与权限（本应用授权）
│   └── 工作空间管理（空间管理员）
│       └── 成员身份 / 空间角色 / 应用授权概览 / 空间资料与审计
├── 全局管理（全局管理员）
│   └── 全部工作空间 / 集群 / 输出仓库 / 应用根域名与策略 / 全局审计
└── 接入指引（独立帮助入口）
```

工作空间与应用是唯一两层业务组织结构。构建记录、产物和配置是应用内视图；管理和个人设置是任务入口，不成为新的业务组织层。未授权的应用不会出现在列表，应用空数据时不自动选中其他应用。

日常页面不展示管理侧栏、集群列表、仓库配置或成员设置。顶部只保留品牌、空间切换、当前应用面包屑与账户/管理操作，不设置“应用 / 构建”全局页签。进入应用详情后，在页面内切换概览、发布、构建、日志、监控、变量与配置。窄屏从空间菜单进入管理，仍保留所有个人功能。空间管理仅空间管理员可见，平台管理仅全局管理员可见；直接访问 URL 和后端 API 都独立校验相应领域权限。

### 2.1 三类管理入口与权限

| 管理范围 | 入口 | 内容 | 原型访问限制 |
|---|---|---|---|
| 全局管理（实例级） | 右上角账户菜单 → 全局管理 | 全部工作空间（含创建）、集群、镜像仓库、执行策略、应用根域名/证书、保留策略、全局审计 | 仅全局管理员可见和访问；页面不显示工作空间切换，避免误认为配置仅属于当前空间 |
| 工作空间管理 | 当前空间菜单或空间管理按钮 | 成员身份、空间角色、应用授权概览、空间资料（显示名称与说明）与空间审计 | 空间管理员可访问；不出现集群、仓库、应用根域名或资源策略输入 |
| 应用管理 | 应用列表 → 独立应用详情 | 概览、发布、构建、日志、监控、变量、运行/构建配置、本应用构建密钥及成员授权 | 按应用权限；全局托管摘要只读，自定义域名仍是应用能力 |

原型账户菜单提供“切换身份预览”：全局管理员、工作空间管理员、应用查看者。预览只改变本地内存角色；真实后端仍需独立执行 instance/workspace/application 权限检查。工作空间授权不隐式取得全局权限。

全局路由为 `#/platform` 及其子路由；旧 `#/nodes`、`#/platform/nodes` 跳转到 `#/platform/clusters`，旧 `#/registries` 跳转到全局仓库页，继续受全局权限检查。空间管理沿用 `#/management`、`#/settings` 等现有原型路径。三类是管理范围，业务组织仍只有工作空间与应用两层。

### 2.2 个人账户域（2026-10-25）

个人账户属于当前实例的用户身份，不属于某个工作空间。全局管理只对全局管理员开放，个人账户对每位已登录用户开放，二者不是同一个权限域。

- 个人页使用 `#/account`、`#/account/connections`、`#/account/tokens`；不展示空间切换、空间管理按钮或空间侧栏。
- PAT（以及之后的 Agent 授权连接）归属 user_id；具体授权可以选择有权访问的工作空间/应用作为资源范围。资源范围不会改变个人凭证的归属。
- 工作空间管理员不能因管理某空间就管理其他成员的个人资料或令牌。移出工作空间会收回该空间访问权，个人账户及其其他空间身份仍保留。
- 原型只有一个示例空间，所以具体授权表单明确显示该目标空间；它不是个人账户页面的父级上下文。旧 `#/connections`、`#/tokens` 跳转到对应个人路由。
- 接入指引是独立帮助页，不作为某个工作空间拥有的用户数据。当前个人资料只读演示；真实个人信息编辑、会话与安全设置按后端身份能力实施，不宣称已实现。

## 3. Railway 参考与取舍

本次直接参考用户提供的两张 Railway 截图，不把截图当作竞品当前完整功能的实测。借鉴其空间切换、应用入口和应用内信息组织，采用本轮确认的中性浅色视觉。

| 截图中的优点 | Yummy 落地 |
|---|---|
| 首页聚焦业务对象，设置收进菜单 | 工作空间首页直接展示应用，不设长期管理侧栏 |
| 选中服务后集中处理服务操作 | 点击应用进入独立详情页面，所有操作都保留该应用身份；不采用侧面板 |
| 详情内分任务页签 | 首期在同一应用中切换发布、构建、日志、监控、变量与配置，产物属于构建子视图 |
| 有明确的新建入口和状态 | 管理员创建应用，开发者在应用内创建构建；当前运行版本与最近构建结果分开，构建失败不代表应用已离线 |

第一版没有服务依赖关系，不制作空拓扑画布或伪造资源连线。应用卡片保留名称、说明、当前运行状态/版本与最近构建两个维度，辅以类型与配置状态；支持列表视图。未来拓扑必须有真实部署/依赖模型再加入。

最新字段归属与资源边界见 [创建与配置边界复核](2026-10-24-application-configuration-boundaries-design.md)。

## 4. 关键交互

### 4.1 应用首页与详情

- 首页可搜索名称和说明、切换卡片/列表；清除搜索恢复可见应用。管理员创建应用只填名称（1～30 位小写字母、数字和中划线，字母开头、字母或数字结尾，不能有连续中划线；空间内唯一，创建后不能修改；输入框失焦时就地提示），继承当前空间，创建后直接进入运行配置页预览；端口、类型、变量在创建后确认，集群/仓库不作为应用配置。
- 点击应用跳转到独立应用详情页，页面不叠加在应用列表上。详情、创建构建和单次构建详情共享应用名与功能导航；刷新及直达链接保持同一应用身份。返回应用列表恢复原搜索和卡片焦点，Escape 只处理菜单/对话框，不把页面当作抽屉关闭。
- 应用页显示空间、应用名、运行状态与配置摘要；默认打开概览。首期页签为概览、发布、构建、日志、监控、变量、配置，后续托管数据库绑定仍在应用内扩展。查看者只读，没有创建按钮，配置输入禁用。
- 页面正常纵向滚动，构建表格仅在自身容器横向滚动；桌面与手机都使用完整详情页，不保留背景列表或模态焦点陷阱。
- 集群和仓库只以平台托管摘要出现在应用与构建配置里；接入集群、修改平台仓库口令等操作留在全局管理。

### 4.2 创建构建与结果

- 构建并部署固定继承当前应用，表单不再提供应用切换下拉；默认勾选构建成功后部署，也可仅构建。提交时绑定运行配置版本；上传源码包，或通过 Agent/CLI 在本地打包。返回列表再进入其他应用时清除原示例源码选择，避免归属混用。
- 基础区保留 Dockerfile、上下文；目标架构、构建集群和系统镜像路径按实例策略只读展示，目标阶段、参数、密钥引用放高级区；右侧集中确认源码和镜像目的地。
- 失败保留输入并定位具体原因；不静默替换资源，不因超时重复提交。上传和入队分别反馈，幂等键由客户端生成并复用。
- 构建记录只展示当前应用，可按状态和编号/说明筛选；不提供独立的全局构建列表。单次构建详情和创建构建仍位于应用详情布局下，返回本应用构建记录。详情显示阶段、增量纯文本日志、源码/配置快照和产物。日志与明确错误证据分开，不把建议当作根因，不执行日志 HTML/ANSI。
- 构建成功仅表示镜像已推送并校验；选择自动部署时继续显示关联 release 及其进度，不提前宣告应用上线。取消构建先确认，再等待实际停止回执。断线保留内容，失联不宣称已停止。

### 4.3 工作空间管理

空间管理按团队身份、应用授权概览与空间资料组织操作；平台管理另设集群、仓库和平台设置入口，仅全局管理员可见，提供明确“返回应用”。进入后才显示管理侧栏。成员表分列空间角色和应用访问权；具体应用授权在应用的成员与权限页操作，由空间管理员进行；空间成员页不再维护另一套授权表单。

全局管理中的集群页显示 worker 连接、集群内机器（只读）以及构建、运行、入口与采集能力，离线集群不消失；集群和输出仓库由实例执行策略统一引用；构建密钥默认由应用拥有，只在本应用构建设置维护，应用根域名和证书方案由管理员准备。全部工作空间页可创建工作空间：填写空间名（命名规范，创建后不能修改）和可选的显示名称；空间设置只能改显示名称与说明。凭证只替换不回显，撤销与停用说明影响。普通管理表单使用 Sheet，复杂配置使用页面；危险操作用确认对话框。管理界面也需覆盖加载、空数据、请求失败、已过期和无权限。

构建密钥入口已移到应用的构建设置，只列本应用的名称/用途/版本；构建提交只引用本应用密钥。第一版不显示空间共享密钥池。应用授权入口为配置 → 成员与权限；空间成员页的概览与应用页共用数据。应用权限移除不删除空间成员，空间管理员的继承访问不允许在应用中移除。

### 4.4 登录与个人 Agent 接入

登录保留本地账号；配置了外部 OIDC 才显示团队身份登录，普通登录返回应用首页。个人 Agent 接入与 PAT 在账户菜单，普通成员也能使用，不必进入空间管理。应用标题另提供“连接 Agent”，弹出带当前空间名与应用名的 CLI 与本地 MCP 命令。

第一版 Agent 接入页按顺序说明：安装 CLI → 在访问令牌页创建 PAT → `yummy login` 粘贴令牌 → `yummy use <空间名>/<应用名>` → `yummy deploy`，或把 `yummy mcp` 配置给 Agent。远程 HTTP MCP、OAuth 同意页和已授权连接属于第一版之后，原型中保留并标为“后续版本”供评审：远程方式显式选择有权访问的工作空间与应用作为授权范围，生成应用专属 URL；同意页展示客户端来源、账号、空间/应用与具体动作，离线访问单独同意；完成后返回客户端，不展示 token；连接撤销需确认且不自动取消已有构建。

### 4.5 部署、变量与基础监控

概览区分当前服务版本与最近构建/发布结果；发布失败时仍能看到旧版本正在运行。发布详情列出镜像、运行配置版本、运行位置及实例/健康/访问阶段。回滚确认说明镜像和配置版本一起恢复、未发布草稿保留，数据库和卷不回退。

变量/配置保存产生新版本并展示待部署更改，当前实例不改变；“检查更改”对比变量、端口、域名、健康、资源、文件和卷，再确认用当前镜像部署。可二次确认放弃全部草稿，保留当前实例；敏感差异仅显示已替换。确认绑定所检查版本，并发变更后重新检查。普通值可编辑，敏感值只替换，批量导入先预览键差异。运行配置覆盖端口、可选自定义域名、探针、资源、文件与持久卷；默认地址由系统生成，只读展示；配置文件只读挂载，解除卷挂载仍保留底层数据。

运行日志与构建日志分开。原型演示当前实例、跟随暂停和已加载结果查找；正式实现增加实例/版本/时间查询和游标。监控提供 1 小时/24 小时 CPU 与内存趋势、采集时间、就绪、重启和入口探测；缺测不补 0。图中样本是明确标记的静态数据，不验证实际采集精度。

普通查看者只读；发布、运行操作与配置修改使用不同权限。首期不提供伪造 QPS/请求 P99、Trace 或复杂告警入口。

## 5. 视觉、响应式与可访问性

- 第一版采用中性浅色：白色表面、浅灰背景、深色正文和主操作、蓝色链接/焦点；成功/警告/失败使用语义色与文字。日志使用深色阅读面。后续再提供浅深主题切换，本版不设置主题切换入口。
- 正文与表单以 14 px 为基准，辅助信息 13 px、徽标 12 px；主标题 24～28 px。语义变量映射 shadcn/Tailwind token，后续主题通过替换变量实现。
- 日常顶部约 64 px，内容最大 1320 px；应用卡片桌面三列、中等屏幕两列、手机一列。管理侧栏约 224 px，仅管理模式存在。
- 应用详情使用完整页面，应用标题下放功能导航；所有子页面沿用该导航，构建内部再展示日志、输入快照等内容。手机保留同一层级，小屏不删掉权限、资源或个人凭证功能。
- 复用 shadcn 语义 token、固定间距与 Lucide 描边。ID、路径、命令才用等宽字体，不加入装饰性指标卡、假图表或空模块导航。
- 所有输入有 label，菜单可通过键盘开关，Escape 可关闭菜单与确认对话框，焦点可见，跳转主要内容可用；支持 reduced-motion。本轮实测主要语义文本色对比度、焦点路径和窄屏布局；正式实现仍需完整 WCAG AA 与读屏验证。

本轮竞品差距、交互调整与未实现项见 [体验复评](2026-10-23-paas-competitive-ux-review.md)。

## 6. 前端技术选型

以当前 demo 的 React 19、TypeScript、Vite 和 Protobuf 客户端为基础，添加成熟组件，不新增 Node SSR 生产服务。

| 类别 | 推荐 | 使用边界 |
|---|---|---|
| 应用框架 | React + TypeScript + Vite | 保持 SPA，可由 Go 嵌入或独立静态托管；不为后台引入 SSR |
| 路由 | TanStack Router | 类型化路径、搜索参数、嵌套路由、权限前置检查、代码分割 |
| 服务端状态 | TanStack Query + Connect Query 官方适配 | 查询缓存、失效、轮询、取消等待、错误处理；不把缓存当权限事实 |
| 表格 | TanStack Table + shadcn Table primitives | 服务端分页/排序/过滤；按所锁定主版本 API 实现，不直接混用旧版示例 |
| 表单 | TanStack Form + Zod | 字段/跨字段验证，复杂构建表单复用字段组件；后端独立校验 |
| 样式 | Tailwind CSS 4 + CSS 语义变量 | 使用官方 Vite 插件；主题 token 统一，避免散落的硬编码色值 |
| 组件 | shadcn/ui，选择一套底层 primitive 家族 | 优先采用其 Radix 系组件与模式；只引入需要的 Sidebar、Tabs、Sheet、AlertDialog、Select、Popover、Command、Table、Tooltip、Sonner 等组件 |
| 资源图表 | shadcn Chart + Recharts | 生产复用成熟图表、时间轴/Tooltip/缺测与单位；当前静态原型用 SVG 展示示例，不自研产品图表引擎 |
| 图标 | Lucide React | 统一描边与尺寸，图标配文字/可访问名称 |
| 日志显示 | 普通文本 + 有界增量列表；必要时 TanStack Virtual | 第一版不执行 ANSI、不引入完整终端，避免假终端交互 |
| 全局状态 | React 状态/Context + URL + Query | 暂不额外引入 Redux/Zustand；出现明确跨页复杂状态时再评估 |
| 验证 | 保留 Vitest/Testing Library，补 Playwright | 前者验证组件行为，后者覆盖跨页业务流程与响应式 |

技术版本以稳定发布和兼容验证为准，提交 lockfile 固定具体值。此次核查的官方文档标识 Router v1、Query v5、Form v1、Table v9、Tailwind 4；这不表示这些依赖已在本仓库安装或通过兼容测试。尤其 Table 的旧版示例与新版 API 需要核对，不能按“latest”无条件升级全部依赖。

选择 TanStack Form 是为了统一类型化表单方案；不再并装 React Hook Form 处理同一类表单。shadcn 是可维护的组件源码体系，组件落入仓库后仍需要负责一致性和可访问性。

```text

/platform/settings
/platform/audit
/w/$workspaceId/apps
/w/$workspaceId/apps/$applicationId
/w/$workspaceId/apps/$applicationId/releases
/w/$workspaceId/apps/$applicationId/releases/$releaseId
/w/$workspaceId/apps/$applicationId/logs
/w/$workspaceId/apps/$applicationId/monitoring
/w/$workspaceId/apps/$applicationId/variables
/w/$workspaceId/apps/$applicationId/settings/runtime
/w/$workspaceId/apps/$applicationId/settings/build
/w/$workspaceId/apps/$applicationId/settings/access
/w/$workspaceId/apps/$applicationId/builds
/w/$workspaceId/apps/$applicationId/builds/new
/w/$workspaceId/apps/$applicationId/builds/$buildId
/w/$workspaceId/apps/$applicationId/artifacts
/w/$workspaceId/manage
/w/$workspaceId/manage/members
/w/$workspaceId/manage/audit
/w/$workspaceId/manage/settings
```

应用详情与所有应用操作使用嵌套路由，共享同一应用页面布局；直接打开 URL 也能定位详情。构建详情 URL 的 application_id 必须与构建记录归属一致，不能凭 build_id 跨应用读取。当前原型使用 hash 和可读应用名方便本地查看，正式使用稳定 application ID。发布、基础监控和后续数据库绑定都是应用子路由，不插入新的组织层。

筛选、排序、分页进入类型化 URL；原型通过内存保留应用搜索/视图。Query key 包含身份权限版本、workspace_id、application_id 与对象 ID。切换空间/退出清理缓存，切换构建取消旧日志请求。权限来自后端 capabilities；按钮与路由 guard 仅改善体验，真正的隔离由后端执行。

写操作成功后精确失效关联查询，不提前乐观宣告构建成功、任务停止或权限已保存；前端不复制 Casbin 策略，不在 localStorage 保存 PAT 或会话秘密。
