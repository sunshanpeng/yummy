## 1. 目标与范围

让个人开发者和可信团队通过网页、CLI 或 Agent，把本地源码与 Dockerfile 上传到自有服务器，完成服务端构建、部署运行、域名访问，以及配置、排错、监控和版本恢复。

```text
管理员接入 k3s 集群，准备仓库、应用根域名与成员授权
→ 开发者配置应用端口、健康检查和变量
→ Agent 预览并上传本地源码与 Dockerfile
→ AMD64 服务端构建、推送并校验镜像
→ 用镜像 digest + 运行配置版本创建发布
→ 新实例就绪、入口/HTTPS 验证
→ 返回运行版本、访问地址、日志和基础监控
→ 后续更新、变量变更发布、回滚、停止与启动
```

第一期对外可用的边界是“应用能运行且能维护”，不是镜像产出。构建成功、发布结果、当前运行版本和访问健康分别记录与展示。技术与验收细节见 [首期运行方案](2026-10-23-paas-v1-runtime-design.md)。

Apple Silicon 可以跨平台构建，但用户不需要在电脑安装 Docker 或配置模拟器；本地只打包，首发认证目标为在 AMD64 Linux 机器上原生构建与运行。目标架构属于明确配置，不静默采用客户端架构。

### 1.1 第一版承诺

- 多用户、两层工作空间/应用、应用权限、个人访问令牌（PAT）、最小 CLI 与本地 stdio MCP。
- 本地源码上传、Dockerfile 服务端构建、镜像验证及构建并部署。
- 单容器 HTTP 服务、静态站点容器、后台进程；每应用一个运行实例。
- 运行变量与敏感值、端口、命令、资源限制、健康检查、域名/HTTPS、配置文件和基础持久卷。
- 发布历史、重新部署、镜像与配置版本回滚、重启、停止与启动。
- 运行日志、CPU/内存历史、就绪/重启/异常事件及 HTTP 探测；缺测与离线明确区分。
- 所有应用操作集中在独立应用详情页；人员管理收进工作空间管理，集群、仓库等基础设施收进全局管理。
- 控制面和 worker 两类常驻产品进程；优先嵌入成熟库并复用现有 k3s。

### 1.2 暂缓范围

Git 自动化与预览环境、自动语言构建、多容器 Compose、任意流水线、多架构/QEMU、托管数据库、多副本/跨集群迁移、多环境与同一应用多个部署、浏览器 OAuth 与远程 HTTP MCP、复杂告警/外部通知编排、APM/Trace、通用 CMDB、企业 SCIM、商业计量和内置大模型聊天。应用可以用变量连接外部数据库，数据不必等到托管数据库功能才可使用。

这是可信团队自托管产品，不以首期提供面向互联网陌生租户的恶意代码托管隔离保证。

## 3. 用户、角色与资源模型

```text
平台实例
├── 用户、会话、个人账户（PAT）、实例管理员
├── 平台管理：集群、环境、输出仓库、应用根域名、资源策略与配额
└── 工作空间（空间名不可改，显示名称可改）
    ├── 应用（应用名不可改）
    │   ├── 应用访问授权：maintainer / developer / viewer
    │   ├── 构建默认配置与应用构建密钥
    │   ├── 构建记录 → 源码快照、执行记录、日志、镜像产物
    │   └── 部署 default（第一版每应用一个，环境 prod）
    │       ├── 发布记录 → 镜像 digest、运行配置版本、当前运行实例
    │       └── 变量 / 配置 / 运行日志 / 基础监控
    └── 工作空间管理（管理员入口）
        ├── 成员、空间角色、应用访问授权
        ├── 应用授权概览（跳转应用内配置）
        └── 空间设置、操作审计
```

业务导航仅“工作空间 → 应用”两层。应用直接归属工作空间，不再建立 Project、项目成员或项目资源授权；构建、产物是应用内的业务记录。资源管理与个人凭证是配套功能，不增加业务组织层级；环境与部署描述应用运行在哪里，也不是组织层级。

### 3.1 角色规则

实例管理员负责实例配置、用户停用与工作空间创建，其操作记录审计。空间角色为 admin / member：admin 管理本空间成员、应用与授权，不管理集群、环境、仓库与应用根域名；member 通过具体应用的 maintainer / developer / viewer 授权取得访问权，不默认看到空间内所有应用。

| 操作 | 空间 admin | 应用 maintainer | 应用 developer | 应用 viewer |
|---|---|---|---|---|
| 查看本应用构建、日志和产物 | 是 | 是 | 是 | 是 |
| 下载本应用原始源码快照 | 是 | 是 | 是 | 否 |
| 上传源码、提交/取消/重新构建 | 是 | 是 | 是 | 否 |
| 修改本应用构建/运行配置、变量、域名和卷 | 是 | 是 | 否 | 否 |
| 查看部署、运行日志和监控 | 是 | 是 | 是 | 是 |
| 发布、回滚和重启 | 是 | 是 | 是 | 否 |
| 停止/启动应用 | 是 | 是 | 否 | 否 |
| 创建/归档应用 | 是 | 否 | 否 | 否 |
| 邀请/移除成员、分配空间角色及应用访问权限 | 是 | 否 | 否 | 否 |
| 管理集群、环境、输出仓库、应用根域名及实例策略 | 否，仅实例管理员 | 否 | 否 | 否 |
| 管理本应用构建密钥（新建/替换，不读已有明文） | 是 | 是 | 否 | 否 |
| 查看密钥明文、导出仓库口令 | 否 | 否 | 否 | 否 |
| 创建自己的限定访问令牌（PAT） | 是 | 是 | 是 | 是，仅只读 |

第一版由管理员仅填名称创建应用，基础资源继承实例策略，开发者专注已有应用的构建。应用维护者可修改业务构建/运行参数；开发者可在单次构建中选择目标阶段、非敏感参数及已授权密钥引用。集群、架构和输出仓库按实例策略解析，不提供应用或单次构建覆盖。空间层管理成员身份与空间角色；具体应用授权在应用的成员与权限页完成，空间成员页提供同一份授权数据的概览和跳转。修改应用授权仍需要空间管理员权限，应用维护者不默认拥有授权他人的能力。

令牌每次调用重新计算“用户当前有效权限 ∩ 令牌应用范围 ∩ 令牌动作范围”。最后一位空间管理员不能被移除或降级。普通成员访问管理页时拒绝，不能只隐藏入口而保留接口权限。

### 3.2 第一版资源字段

| 对象 | 必需信息与行为 |
|---|---|
| 工作空间 | 空间名（命名规范，实例内唯一，不可改）、显示名称（可改）、成员、空间角色、配置；只归档不删除，归档后名称继续占用 |
| 应用 | 应用名（命名规范，空间内唯一，不可改）、说明、工作空间、访问授权、归档状态、Dockerfile/上下文路径、构建参数、密钥引用、默认部署（冻结的集群与命名空间、运行配置版本、当前服务 release、变量/自定义域名/卷）；平台生成应用 ID、默认地址后缀与镜像路径 |
| 集群 | 名称、worker 身份、集群标识、机器列表（只读：OS/架构/容量/就绪）、构建/运行/入口/监控能力、连接和就绪状态；第一版每个实例一个 |
| 环境 | 标识、显示名称、运行集群、应用根域名；第一版只有默认环境 prod，界面不显示 |
| 镜像仓库 | 名称、HTTPS 地址、仓库前缀、凭证、实例策略引用、检测结果；凭证仅替换，不回显 |
| 构建密钥 | 所属应用、名称、用途、版本、最近修改；仅输入/替换值，按本应用引用 |
| 构建 | 所属应用、来源、发起用户/客户端或令牌、不可变配置、执行集群与机器、阶段、日志、产物、错误码及重建关联 |

集群、环境与输出仓库归属实例，由实例管理员接入和配置；工作空间成员按动作权限间接使用，不能修改配置。业务构建密钥默认归属应用，应用只引用自己的密钥版本；跨应用共享后续有明确需求再设计。创建应用只填名称，不分配用户可修改的集群或仓库。一个集群对应一个 k3s 集群和其中的一个 worker，集群内机器由 k3s 管理，平台只读展示；第一版每个实例接入一个集群，构建和应用都在其中运行。不提供通用 CMDB 编辑器、主机终端或资产扫描。离线集群仍保留记录。

## 4. 账号、登录与 Agent 接入

### 4.1 初始化与邀请

1. 安装者在服务器本地通过管理 CLI 创建首位实例管理员，不开放匿名“抢注首位管理员”接口。
2. 管理员登录网页，创建默认工作空间。
3. 管理员生成限时、单次使用的邀请链接；被邀请人设置账号密码，或以已有账号接受邀请。
4. 第一版不依赖邮件服务；链接由管理员自行交付，产品不自动向外部通讯渠道发送消息。
5. 用户可以修改密码、退出登录；管理员可以停用用户和发起密码重设。账号停用立即撤销会话和令牌。

不提供公开注册、默认口令、自动长期令牌和无审计的后台身份切换。

### 4.2 Agent 接入

第一版 Agent 接入只有最小 CLI 与本地 stdio MCP，都使用 PAT：用户在“访问令牌”页创建 PAT，限定工作空间、应用、动作和有效期，明文仅显示一次，可随时撤销；`yummy login` 通过安全输入保存令牌，无人值守时用环境变量传入，不写进项目源码。本地 stdio MCP 复用 CLI 凭证。命令范围见 [命名、集群与最小 CLI](2026-10-26-naming-cluster-and-minimal-cli-design.md)。

浏览器授权码 + PKCE 登录与远程 HTTP MCP（OAuth）放到第一版之后：届时用户从“Agent 接入”页复制应用专属 MCP 地址，客户端打开浏览器登录，再确认客户端、应用和权限；授权连接可单独撤销，权限始终受用户当前角色约束。远程服务不接受本地目录路径并尝试读取电脑磁盘，本地文件仍由 CLI/stdio 上传。协议、选型与端点见 [OAuth 与 MCP 方案](2026-10-23-oauth-mcp-auth-design.md)。

保留本地账号登录；可选配置外部 OIDC 身份登录，平台不会自动给外部账号授予空间权限。令牌管理以及之后的 OAuth 授权与客户端管理均在现有控制面内，不增加独立身份进程。

个人账户独立于工作空间；PAT（以及之后的 Agent 授权连接）由 user_id 拥有，授权空间/应用只是访问范围，空间管理员不能据此管理其他用户的个人凭证。

## 5. 完整用户流程

### 5.1 管理员完成应用运行准备

“开始使用”页面按顺序列出：实例管理员接入集群 → 配置仓库与应用根域名/HTTPS → 创建工作空间 → 空间管理员创建应用与授权成员 → 配置运行参数 → 安装 CLI 并连接 Agent。每项可查看状态和失败原因。

集群接入使用短时注册凭证，集群内的 worker 主动连接控制面。worker 分别检查构建、运行、入口和采集能力；构建需通过架构、构建器、存储、网络和仓库推送检查（逐台机器检查，构建 Job 只调度到通过检查的 amd64 机器），部署另需运行与入口资格通过。“在线”与“可构建”分别展示。管理员可以暂停新任务、撤销接入凭证和轮换证书。

创建应用固定当前空间，只要求名称；名称符合命名规范，创建后不能修改，系统同时生成默认地址后缀。创建后进入本应用配置页预览默认值，确认类型与 HTTP 参数。可以先创建应用再准备资源；提交构建/发布时才检查所需集群与实例策略，缺失时给出管理员处理入口，不在空列表里默认选择。

### 5.2 Agent 从本地目录发起

1. 读取本地代码说明和构建配置，确认应用与目标架构。
2. 若缺少 Dockerfile，由编程 Agent 在用户授权的代码目录内生成；平台本身不调用大模型生成 Dockerfile。
3. 执行预览，展示工作空间/应用、已绑定的运行配置版本、构建后是否部署、文件数量、大小、忽略规则、Dockerfile、目标架构、构建集群与镜像目的地。
4. 按 `.dockerignore` 语义打包，并应用平台的密钥文件排除规则；第一版不支持符号链接及特殊文件，发现后明确报错。
5. 上传源码包，得到验证通过的源码快照 ID。
6. 以幂等键创建构建，立即取得构建 ID 和详情地址；客户端可以退出。
7. 查询构建与关联发布；构建成功后按所选意图部署，确认就绪/访问状态，返回 release ID、镜像 digest、真实业务地址或结构化失败结果。

上传根目录应当是用户明确授权的源码根目录。上下文和 Dockerfile 必须在根目录内；不允许 `../`、绝对路径或链接跳转读取其他目录。第一版将 Dockerfile 进一步限制在选定构建上下文内。

### 5.3 网页发起

用户打开应用，点击“创建构建”：

1. 固定使用当前应用，上传 `.tar.gz` 源码包，或切换到“Agent / CLI”查看本机操作命令。
2. 查看包验证结果、文件清单摘要、Dockerfile 和构建上下文。
3. 只读查看平台架构、实例策略解析出的构建集群与系统镜像路径；高级区可填写非敏感构建参数、目标阶段及密钥引用。
4. 默认选择“构建成功后自动部署”，也可仅构建；自动部署前需确认运行配置，提交时固定运行配置与实例策略版本。点击“开始构建并部署”，在同一应用内跟踪两阶段结果。

网页不模拟读取任意本地路径。源码包必须满足同一套文件与配额规则；格式或内容不合规时保持表单、显示具体原因，不创建构建任务。

### 5.4 结果、取消与重建

- 成功：复制 `registry/repository@sha256:...`，同时显示唯一构建标签、平台、构建输入和镜像验证结果。
- 失败：显示失败阶段、错误码、相关日志与事实性的检查建议；Agent 可修复本地源码并重新提交。
- 重新构建：沿用原源码快照和配置创建新记录，显示来源构建 ID；不覆盖旧日志。源码已过期时要求重新上传。
- 取消：先显示“正在取消”，只有确认任务停止后才显示“已取消”。worker 或机器失联时提示执行状态未知，不承诺进程已停止。
- 服务断线：页面进入恢复查询状态，保留已有内容；不能显示为成功，也不主动重复提交构建。

### 5.5 运行、配置与发布恢复

变量与运行设置先保存为新版本，显示未部署更改；当前应用继续使用原 release。部署更改复用已验证镜像，不因改运行变量重建。回滚以选定 release 的镜像与配置版本创建新发布，保留未发布草稿，不回退数据库或持久文件。应用状态、运行日志、资源指标和访问状态都在应用内查看；首期提供基础持久卷，停止/回滚不删除数据。详见 [首期运行方案](2026-10-23-paas-v1-runtime-design.md)。

## 7. 状态、提示与默认限制

构建主状态为：排队、启动中、执行中、恢复确认中、正在取消、成功、失败、已取消、超时、执行状态未知。执行阶段细分为准备源码、Dockerfile 构建、推送镜像、校验产物，不伪造精确百分比。

首发建议值均为产品默认值，不是实测容量结论：

| 限制项 | 建议默认值 |
|---|---|
| 压缩包 / 解压数据 / 文件数量 | 256 MiB / 1 GiB / 50,000 个 |
| 每集群构建并发 | 1，可由管理员在资源检查通过后调整 |
| 排队 / 执行 / 取消确认窗口 | 30 分钟 / 30 分钟 / 30 秒；失联另走恢复确认 |
| 源码 / 日志 / 构建元数据 / 审计保留 | 7 天 / 30 天 / 90 天 / 90 天 |
| 日志上限 | 每次 20 MiB；超过后标记截断，仍继续收集任务状态 |
| PAT | 默认 30 天，可提前撤销，最长 90 天 |
| 应用资源历史 / 运行日志 | 24 小时 / 24 小时且每应用最多 50 MiB，清楚标记截断与缺测 |
| OAuth access / refresh token | 建议 15 分钟 / 最长 30 天；刷新需单独同意，可提前撤销 |

源码及日志到期后仍保留元数据与“已过期”状态。平台不会因删除记录自动删除外部仓库镜像；镜像生命周期交由仓库管理，页面明确此边界。

## 8. Agent 契约

CLI 与 MCP 都返回稳定 ID、结构化状态、错误码、可重试性、分页/日志游标和有界的结果。认证信息不出现在命令示例或日志里。

运行工具另包含发布、回滚、运行状态/日志/指标与配置版本管理，使用明确的部署/运行/配置 scope，不默认授予写权限。具体权限与接口见 [首期运行方案](2026-10-23-paas-v1-runtime-design.md)。

建议构建 MCP 核心工具（第一版通过本地 stdio MCP 提供）：`list_applications`、`get_build_config`、`preview_build_context`、`submit_build`、`get_build`、`read_build_logs`、`cancel_build`、`retry_build`。它们作用于已配置的工作空间与应用上下文，不把成员管理和任意主机执行开放为默认 Agent 工具。

Skill 描述如何识别应用、准备 Dockerfile、检查上传文件、提交、读日志与修复；权限仍由服务端执行。日志与源码中的自然语言作为数据处理，不能授予新权限。

## 9. 验收与交付顺序

第一期内部依次完成：M0 构建/运行/TLS/采集资格验证 → M1 身份资源与源码构建 → M2 配置变量、部署与运行日志 → M3 基础监控、回滚和 Agent 操作 → M4 恢复、配额与团队试用。它们是完整首发的研发步骤，不能把 M1 当作对外可用版本。

最终验收需让非作者用 Apple Silicon 上传 Go HTTP、Node HTTP、静态站点和后台进程，在 AMD64 机器上完成构建与运行；验证 HTTPS、变量修改不重建、运行日志、资源趋势、错误新版本恢复、镜像/配置回滚、PVC 保留及权限隔离。完整矩阵见 [首期运行方案第 8 节](2026-10-23-paas-v1-runtime-design.md)。

## 10. 本稿的设计决定

- 第一版是可运行的自托管 PaaS：源码构建、发布、配置、日志、基础监控与更新恢复共同交付。
- 继续使用当前 demo 的 Go、React、ConnectRPC、PostgreSQL、Redis 及模块化单体形态。产品仅控制面和 worker 两类常驻进程，后台循环以及第一版之后的 OAuth、HTTP MCP 都集成在控制面。
- 构建在接入的 k3s 集群内以每次任务独立的 BuildKit Job 运行，先完成环境资格验证。
- 前端按 React + TanStack + Tailwind + shadcn/ui 设计；原型与产品运行代码分开。
- 应用、构建、产物、发布与运行配置版本分开建模；为数据库绑定、观测关联、资源管理及页面模块扩展保留边界，见技术方案第 15 节。
- 先接入现有 OCI 仓库；提供准备指南，不在第一版自研镜像仓库服务。
- 基础人员与权限面向可信团队；通用企业流程、开放 SaaS 隔离和商业版本划分后置。

以上均可在评审中调整。完成本稿不代表已经批准执行部署、安装依赖或开发全部功能。
