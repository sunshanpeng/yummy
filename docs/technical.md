# Yummy 技术文档

本文维护当前技术契约、实现位置和验收边界。用户路径和权限见 [产品文档](product.md)，部署与排障见 [运维手册](operations.md)。

## 1. 进程与代码分层

控制面以模块化单体运行，内嵌 Web SPA、Connect API、HTTP 传输、后台调度和清理、OAuth、按应用绑定的远程 MCP，以及独立监听的 mTLS worker 网关。worker 在执行宿主机主动连接控制面，负责调度到 Kubernetes 的任务和运行资源、观察与回报。CLI 按需启动；构建 runner 与 BuildKit 受构建任务调用。模块依赖、监听与外部系统见 [部署和代码分层图](architecture.md)。

| 代码位置 | 职责 |
| --- | --- |
| `cmd/`、`internal/controlplane/` | 分发入口、启动装配和 Web 静态产物 |
| `internal/transport/`、`internal/bff/mcp/` | Connect、客户端与 worker 网关；远程 MCP 使用现有领域入口编排 |
| `internal/domains/` | 工作空间、应用、构建与源码、部署与运行配置、用户授权审计、集群库存和登记等业务事实 |
| `internal/infra/` | PostgreSQL、Redis、Kubernetes、BuildKit、归档文件和镜像仓库适配 |
| `internal/lib/` | 无业务域依赖的命名校验、配置、密钥处理、运行配置与 OpenTelemetry |

依赖由入口向传输、领域、基础设施流动。领域使用其他领域显式暴露的接口；平台管理和 MCP 不绕过授权或跨域读表。接口由 [Proto](../api/platform/v1/) 定义，`make generate` 生成 Go 与 TypeScript 客户端，`make check-binary-deps` 检查分发边界。

## 2. 数据、配置与授权

- PostgreSQL 保存用户、成员和授权、集群与登记、工作空间与应用、源码清单、构建及尝试、产物、配置版本、发布、操作、观测及审计。Redis 负责会话、登录频控与在线状态；归档字节落在 `source-root` 目录。Goose 通过前向迁移演进 schema，常用访问使用 GORM 与生成 DAO。
- 应用归属工作空间。主键固定；业务键通过唯一约束管理。删除释放名称，保留关联历史的原 ID。部署、发布及构建记录用应用与工作空间作用域校验；发布输入、已验证摘要和运行配置版本可追溯。
- 业务请求进入授权服务后校验数据库中的当前成员关系，使用 Casbin 匹配角色动作。Cookie 会话受 CSRF 与来源保护；PAT 和 OAuth 令牌受 audience、应用 ID 与 scope 限制，并与当前权限求交。OAuth 授权使用授权码和 PKCE；通过资源标识限定远程 MCP，支持受管客户端与 CIMD。OIDC 登录以 issuer 和 subject 绑定本地账号。
- 构建密钥、运行敏感值和仓库凭据由主密钥保护，查询 DTO 不含明文。worker 只在执行需要的阶段取得该任务所需凭据。控制面工作区与源码目录、密钥、数据库应按同一恢复点备份。
- 连接、监听、密钥和证书属于启动配置。优先级为显式命令行 > 配置文件 > 环境变量 > 默认值。运行期平台策略写入数据库的 `instance_settings`，由全局管理员修改并记录审计。配置项及启动方式见 [运维手册](operations.md#2-控制面安装与启动)。

## 3. 源码与构建

CLI 解析用户授权的本地根路径、构建上下文与忽略规则，预览后打包上传。服务端使用同一归档校验验证压缩包摘要、越界路径、文件类型与配额，再生成不可变源码快照。默认限制为压缩 256 MiB、解压 1 GiB、50,000 个条目，实例配置可降低上限。下载授权绑定快照及任务，传输与业务命令使用独立的超时预算。源码到期时进行后台回收，在途构建继续使用已引用的文件。

### 构建方式自动选择

| 输入 | 行为 |
| --- | --- |
| 指定 Dockerfile | 在已选上下文内验证指定文件，交给 BuildKit。路径不存在、越界或文件不合法时拒绝提交 |
| 未指定，且根目录有 Dockerfile | 选择默认文件并验证后交给 BuildKit，构建失败时保留原错误 |
| 未指定，且根目录没有 Dockerfile | Railpack 按需识别并生成计划，再由同一套 BuildKit 执行 |

受理时以服务端已验证的快照冻结方式与上下文。Railpack 规划器为 v0.43.0，配套前端镜像固定摘要。构建产物、推送验证、部署与回滚走共用流程。具体启动参数和可用执行形态见 [运行环境验收](operations.md#71-实机部署形态2026-11-13-至-2026-11-18tencent-sh)。

### 投递、恢复与输出

- 构建受理以幂等键去重。调度根据节点资格、在线、暂停状态与占用情况选择执行目标。策略、源码、构建方式以及自动发布所需的配置和并发条件在受理时快照。
- worker 登记使用一次性注册码并签发 mTLS 身份；安装资格与登记的节点 UID、架构及能力逐项核对。心跳和连接代次用于状态与投递。构建阶段覆盖归档下载、规划或构建、推送、镜像校验。
- 执行消息按任务或尝试标识、连接约束和事件序号验收。worker 的持久 journal 支持断线后重发；控制面以已确认状态恢复。取消或超时先处理在途任务，最终状态取决于执行确认。
- 输出仓库由平台统一配置、校验并加密保存凭据；每应用按不可变 ID 生成专用镜像路径。构建校验输出镜像的摘要与目标架构，发布按 digest 拉取。构建日志按块收集并截断，外部仓库管理镜像保留。

## 4. 运行、发布与资源回收

运行配置保存为独立版本，发布选择已验证镜像和固定配置创建记录。期望运行状态、当前提供服务版本及观测事实分别维护。发布和运行动作带 generation，控制面与 worker 校验当前执行代次；停止请求取代在途发布，旧代次无法恢复实例。失败或回滚后的旧版本、配置与持久卷按对应生命周期处理。关键路径见 [产品操作](product.md#5-配置发布与恢复)。

| 对象 | 命名或边界 |
| --- | --- |
| 运行与构建命名空间 | `<环境>-<空间名>`（首期 `prod`）与 `build-<空间名>`；均为工作空间级资源 |
| 运行对象 | Deployment 为 `<应用名>-<部署名>`（首期 `default`），资源按受管标签、空间、应用及冻结节点校验归属 |
| 构建对象 | 按应用、构建与尝试标识归属；用于重试、对账及清理 |
| 网络 | 运行命名空间允许同命名空间及 Traefik 的入站流量，实际执行依赖 CNI |
| 域名与证书 | 控制面按照登记路由核验入口。使用自定义 HTTPS 时，安装方在运行命名空间预置 TLS Secret 并绑定到域名声明 |

无持久卷的单实例应用采用滚动更新，允许额外一个副本；挂载持久卷的应用采用先停后建，避免多个进程同时写入。配置文件通过 ConfigMap 或 Secret 只读挂载。发布完成至少需要目标副本就绪、镜像 digest 与期望值一致、旧副本退出；HTTP 应用还需匹配的 Service 端点及配置路径的入口验证。恢复旧版本以独立发布记录追踪。

归档保留历史与应用名。活动构建和占用结束后，控制面可受理删除，在 `application_cleanup_jobs` 记录清理阶段并发给匹配的执行节点。任务带短租约和版本，worker 删除前验证连接和租约，检查 Kubernetes 平台标识与工作空间、应用归属，使用 UID 和 resourceVersion 做删除前置条件。清理请求可在掉线后重领，归属冲突、权限不足或 Kubernetes 错误可处理后重试。共享命名空间、网络规则、TLS Secret 继续由相应所有者管理。

存在 PVC 时先保留，应用进入等待确认状态。空间管理员通过独立接口输入应用名后，worker 才处理卷声明。worker 返回资源已清空的结果后，控制面在事务内释放应用名称并写入审计。应用记录、构建与发布历史仍使用原 ID；外部镜像和底层卷的数据回收遵循各自基础设施策略。

提交清理与归档空间持有同一工作空间行锁，已受理但尚未完成的清理任务阻止归档空间。

## 5. 运行观测与平台可观测性

- **应用观察**来自 Kubernetes Deployment、Pod 状态和事件；控制面通过登记的路由探测应用入口。观测保留时间、节点、实例或发布标识，过期后不能当作当前健康。
- **应用日志**来自 Kubernetes 容器日志 API，按 Pod UID、容器、重启序号及块序号去重。worker 的运行日志消息仍用当前操作代次来鉴权，并携带来源 Pod 的发布 ID。新 Pod 出现前继续采集旧 Pod 时，日志仍归旧发布。历史无发布元数据的块仍可无版本筛选地读取。游标绑定应用和筛选条件，控制台跟随从尾部游标增量读取，并按 Pod UID、容器和重启序号分别流式解码 UTF-8。
- **应用指标**由 worker 读取 Kubelet 资源指标，按平台归属标签关联 Pod，CPU 基于相同容器启动身份的 counter 差值，内存是 working set。控制面保存 24 小时采样，按时间窗口返回趋势及缺测状态。
- **平台信号**通过 `internal/lib/observability` 统一。W3C trace context 贯穿 HTTP、Connect、后台与 worker；响应 `X-Trace-Id`、JSON 日志字段与审计关联使用同一 trace ID。管理监听提供 `/healthz`，启用后提供 Prometheus `/metrics`；OTLP push 可独立启用。采集配置与数据限制见 [运维手册](operations.md)。

## 6. 客户端与接口

| 接入 | 契约 |
| --- | --- |
| Web | 登录后使用 Connect RPC。空间、应用、全局管理、个人账户由不同路由承载，授权由服务端校验 |
| CLI | `yummy` 以 PAT 或浏览器 OAuth 登录，承担目录绑定、本地预览、打包和上传；结构化状态提供构建、发布、日志与监控结果 |
| MCP | 控制面 `/mcp/apps/<应用 ID>` 提供 Streamable HTTP；OAuth resource 绑定应用。工具按 scope 暴露，访问使用当下的应用权限 |
| worker | 单独监听上的 mTLS 网关，证书登记、长连接调度、结果与观测回传；不暴露用户业务接口 |

接口使用稳定 ID、带作用域的游标、结构化错误、修订号或资源代次。应用管理、构建、发布与日志分别授权。调用示例见 [README](../README.md) 与 [身份接入](operations.md#身份接入)。

## 7. 前端技术选型

生产界面位于 `web/`，由 React 19、TypeScript 与 Vite 构建为 SPA。Go 发行件内嵌构建产物。Tailwind CSS 4 使用语义变量；控件为入库的 shadcn/ui（Radix）、Lucide 图标和 Recharts 图表。路由、服务端状态、表格和表单分别使用 TanStack Router、Query、Table、Form，表单校验使用 Zod。依赖实际版本见 [package.json](../web/package.json)。

普通产品入口从工作空间应用列表进入应用详情；独立管理路由减少作用域混淆。查询键包含当前作用域，变更后刷新相关列表和详情，授权失败按服务端状态呈现。界面使用中文、中性浅色及语义色彩，适应窄屏并保留键盘导航。旧 HTML 原型仅用于回顾早期交互。
